# openFDA ingestion

Config-driven ingestion for [openFDA](https://open.fda.gov)'s recall
enforcement endpoints — drug, food and device recall reports for the US
(recall reason, classification, status, distribution pattern, recalling
firm).

```
component.py                     OpenFDADataset — the whole component (no shared base; only one openFDA domain)
datasets/defs.yaml               every OpenFDADataset instance, one `---` document each (hand-maintained)
```

Like OpenAQ, `datasets/defs.yaml` isn't generated by a scraper — openFDA has
no multi-dataset catalog to walk, just a fixed, small set of well-known
endpoints (`drug/enforcement`, `food/enforcement`, `device/event`, ...), so
each enabled endpoint is a hand-written instance. Unlike OpenAQ,
`component.py` needs no per-instance dispatch: every openFDA endpoint shares
one plain-paginated-REST shape, so one `openfda_source(endpoint, ...)` call
(`ohdp_ingestion/openfda/source.py`), built on dlt's own `rest_api_source` the
same way CMS's is, covers all of them. Every instance lands through the same
shared destination (`ohdp_ingestion.iceberg_destination`).

## What each instance builds

| | key | group | kinds | materialized | built when |
|---|---|---|---|---|---|
| **source asset** | `sources/openfda/<raw_table>` | `sources_openfda` | `openfda` | never | always |
| **table asset** | `ingestion/openfda/<raw_table>` | `ingestion_openfda` | `dlt`, `filesystem` | yes | `enabled: true` |
| **raw-layer asset** | `lakehouse/raw/openfda/<raw_table>` | `lakehouse_raw` | `iceberg` | runless event | `enabled: true` |

`source -> ingestion -> lakehouse/raw/* -> (dbt clean)`. dlt **replaces**
`RAW.OPENFDA.<raw_table>` on every run — always, never append. An enforcement
report's `status` (e.g. Ongoing -> Terminated) can change after publication
and openFDA gives no reliable `updated_at` to page against, so there is no
row-level cursor to fetch against or dedupe on downstream (same reasoning
CMS/OpenAQ apply).

## The 25,000-row ceiling

openFDA doesn't support paging past 25,000 total matching records with
`skip`/`limit` at all — the documented way past it is sorting by a unique
field and cursoring with `search_after`, which
`ohdp_ingestion.openfda.source.openfda_source` doesn't implement. Every
instance's `row_limit` is therefore capped at
`ohdp_ingestion.openfda.config.MAX_SKIP` regardless of what's configured — a
hard API ceiling, not just a safety cap the way CMS's/OpenAQ's `row_limit` is.
Narrow with `search` (a date range, `country`, `classification`, ...) if a
particular slice matters more than an arbitrary prefix of the full match set.

## The enabled set

Three instances, all `weekly`: `drug_enforcement`, `food_enforcement`,
`device_enforcement`, each scoped to `country:"United States"` and capped at
the 25,000-row ceiling above.

Add another openFDA endpoint (e.g. `drug/event`, `drug/label`, `device/event`)
the same way CDC enables a new dataset: append a `---` document to
`datasets/defs.yaml`, then

```bash
cd data && uv run dagster definitions validate -m ohdp_orchestration.definitions
```

## Notes

- An API key is optional (unlike OpenAQ's, which 401s without one) — openFDA
  just throttles unauthenticated callers harder (40 req/min, 1,000/day vs.
  240 req/min, 120,000/day with a key). When set, sent as an `api_key` query
  parameter (not a header) read off `OHDP_OPENFDA_API_KEY`
  (`platform/helm/README.md`, `.github/workflows/deploy-platform.yml`).
- Paginated by `skip`/`limit` like CMS's offset paging, not page number like
  OpenAQ — `ohdp_ingestion.openfda.source` uses dlt's `OffsetPaginator`. The
  response envelope (`{"meta": {"results": {"total": ...}}, "results": [...]}`)
  needs `data_selector="results"`, like OpenAQ's, unlike CMS's bare array.
