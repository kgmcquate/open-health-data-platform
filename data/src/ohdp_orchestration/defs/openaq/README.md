# OpenAQ ingestion

Config-driven ingestion for [OpenAQ](https://docs.openaq.org)'s `/v3/locations`
— every monitoring station OpenAQ currently indexes worldwide (coordinates,
owning provider, instruments, pollutant parameters). Station metadata only;
OpenAQ's `/v3/measurements` (the actual air-quality time series) is not
ingested here.

```
component.py                     OpenAQDataset — the whole component (no shared base; only one OpenAQ domain)
datasets/defs.yaml               every OpenAQDataset instance, one `---` document each (hand-maintained)
```

Unlike CDC/HealthData.gov/CMS, `datasets/defs.yaml` isn't generated by a
scraper — OpenAQ has no multi-dataset catalog to walk, just the one
`/locations` resource, so there's exactly one instance today and it's edited
by hand. `component.py` produces the identical three-asset shape those
sources use (source / table / lakehouse-raw), built on `dlt`'s own
`rest_api_source` ([`ohdp_ingestion/openaq/source.py`](../../../ohdp_ingestion/openaq/source.py))
the same way CMS's does, and lands through the same shared destination
(`ohdp_ingestion.iceberg_destination`).

## What each instance builds

| | key | group | kinds | materialized | built when |
|---|---|---|---|---|---|
| **source asset** | `sources/openaq/<raw_table>` | `sources_openaq` | `openaq` | never | always |
| **table asset** | `ingestion/openaq/<raw_table>` | `ingestion_openaq` | `dlt`, `filesystem` | yes | `enabled: true` |
| **raw-layer asset** | `lakehouse/raw/openaq/<raw_table>` | `lakehouse_raw` | `iceberg` | runless event | `enabled: true` |

`source -> ingestion -> lakehouse/raw/* -> (dbt clean)`. dlt **replaces**
`RAW.OPENAQ.<raw_table>` on every run — always, never append. `/locations` is
a snapshot of every currently-registered station, not an appended change log,
so there is no row-level cursor to fetch against or dedupe on downstream.

## The enabled set

One instance, `locations`, in the `weekly` cadence bucket — station metadata
doesn't change fast enough to justify daily runs, and a full-catalog scrape
every day would just burn free-tier API quota for no benefit.

Add another OpenAQ resource (e.g. `sensors`, `parameters`) the same way CDC
enables a new dataset: append a `---` document to `datasets/defs.yaml`, then

```bash
cd data && uv run dagster definitions validate -m ohdp_orchestration.definitions
```

## Notes

- Requires an API key — every `/v3` endpoint 401s without one. Sent as the
  `X-API-Key` header, read off `OHDP_OPENAQ_API_KEY` (already wired end to
  end: `.github/workflows/deploy-platform.yml` pulls the GitHub Actions
  secret `OPENAQ_API_KEY` into the shared `ohdp-pipeline-secrets` k8s Secret;
  see `platform/helm/README.md`).
- Paginated by page number (`page`/`limit` query params, `meta.found` for the
  total), not offset like CMS — `ohdp_ingestion.openaq.source` uses dlt's
  `PageNumberPaginator` rather than CMS's `OffsetPaginator`.
